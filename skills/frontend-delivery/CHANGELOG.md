# Frontend Delivery 版本升级日志

当前版本以 SKILL.md 的 metadata.version 为准。本文件记录会影响使用方式、产物结构、状态兼容或维护职责的变化；普通措辞、排版和不改变行为的修正不单独记录。

版本号遵循语义化版本：不兼容的工作流或状态变化升级主版本，向后兼容的能力新增升级次版本，仅修正规则且不改变兼容性时升级修订版本。

## 2.0.0 - 2026-09-08

升级类型：相对 1.0.0 的工作流与状态结构升级，并集中交付 UI、风险、恢复和流程分流能力。

主要变化：
- 将统一五阶段流程改为小改动、常规需求和完整流程三级分流；执行终点继续由评审、计划和完整交付三种模式控制。
- 流程深度使用顺序漏斗：先判断完整流程条件，再判断常规流程下限，只有全部小改动条件同时满足时才进入小改动；无法确定时使用常规流程。
- 权限、资金、隐私或敏感数据、不可逆操作显式进入完整流程；复杂依赖、跨项目契约、实质兼容风险及需分范围确认的关键规则继续使用完整流程。
- 同时修改多个项目、共享内容、公共组件行为、公共配置或产生跨模块联动时，最低使用常规流程；单纯使用公共组件不触发升级。执行中发现新影响或依赖时重新分流。
- 小改动直接处理，回复通常限制为一至三项；常规需求仅在跨会话、交接、多项待确认、等待外部回复或用户要求时创建 task.md；复杂或高风险任务才使用完整产物。
- 改为按任务 ID 和 taskVersion 管理批准及局部失效，未变化任务保留有效授权。
- 计划内容恢复与实施批准分开；已授权范围内、不改变约定的实现细节调整沿用任务批准，实际代码变化仍需核对受影响证据。
- 区分评审产出完成、需求确认、计划完成、实现完成、验证完成和发布就绪；用户只委托实现交接并自行验证时，可结束本次代码交接并保留整体验收待验证。
- 补充中断恢复、按需文件指纹基准、流程升降级及旧状态迁移规则。
- 支持图片、截图、切图和 Figma MCP UI 还原，覆盖来源映射、节点级上下文、组件、变量、资源、多状态核对及视觉证据闭环。
- 支持按来源触发的动效还原，覆盖 Figma Prototype、动效上下文、参考视频、实现映射和实际交互或录屏证据。
- 支持 Figma 来源变更检测；变化先确认是否纳入本次基线，再按影响更新任务、批准和证据。Figma MCP 不可用时可按已有导出资料转图片入口。
- 新增按场景读取的前端风险检查，覆盖异步请求、缓存、金额日期、权限与敏感数据、表单交互、性能多端及发布兼容。
- 新增国际化、主题、浏览器兼容、SSR/Hydration 和 SEO 五个独立触发维度；同时判断项目能力与本次改动相关性，未命中的维度不加载、不验证。
- 衔接项目已有代码评审、CI 和发布要求，不自行创建平台，也不扩大执行权限。
- 统一本 skill 文本为 UTF-8 无 BOM、LF；读取兼容 LF 和 CRLF，业务文件遵循目标项目约定，并适配 Windows、macOS 和 Linux 路径。
- 两份流程图同步展示顺序分流、执行终点、任务级批准、局部失效、UI 与动效、Figma 变化检测和条件性风险。
- 保持网页 URL 还原不在本 skill 范围内。

状态兼容：
- workflow-state.json 使用 schemaVersion 2，并以 taskApprovals 替代旧版全局计划批准字段。
- 恢复旧状态时先保留和核对历史记录；只有能够证明批准范围、计划版本和当前任务一致时，才能映射为任务批准。
- 未知更高 schemaVersion 不做猜测性覆盖。

维护约定：
- 场景风险条目只在 references/frontend-risk-checks.md 维护。
- 状态字段和执行资格只在 references/state-machine.md 维护。
- 验证证据、工程门禁和交付条件只在 references/testing-and-delivery.md 维护。
- ui-restoration.md 引用的设计读取或写入、动效及视频还原属于条件性外部能力；其工具接口或前置 skill 调用约定变化时同步核对该文件，并按本日志的语义化版本规则升级。

## 1.0.0 - 2026-08-31

- 该版本按 2.0.0 前最后一份完整快照追认为 1.0.0，并在发布归档中补充 `metadata.version: "1.0.0"`。
- 所有需求以五阶段流程、两道统一门禁和完整产物为主。
- 使用全局计划批准字段，局部任务的批准、失效和恢复边界较弱。
- 风险检查、接口处理、验证和恢复规则分散在多个参考文件中。
