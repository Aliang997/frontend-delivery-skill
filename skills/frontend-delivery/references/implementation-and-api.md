# 实现与接口对接

只实现当前授权范围。完整流程逐任务核对 state-machine.md 的执行条件；小改动和常规需求沿用直接授权。
操作限制、范围批准和暂停规则统一见 SKILL.md、workflow-gates.md。

## 实现顺序与复用

按依赖顺序完成最小可用改动，沿用项目实际框架、组织方式和错误处理。
页面结构、状态、交互、接口和样式按任务需要安排，纯逻辑修改不创建无关页面。
直接复用适用能力；确需调整公共实现时先查调用方、兼容性和相关回归。不机械规定组件库、公共组件、局部代码的固定优先级。
只有职责确实重复或已有边界要求时抽象；没有复用价值的单次逻辑保持简单。
保留他人修改，只清理本次引入的无用代码和临时资源。读到与记录不同的实现时先核对，不用旧计划覆盖新工作。

## API 核对

真实对接前按接口性质核对以下相关项，明确不适用项，不要求所有接口都具备分页或幂等字段：
- 可信契约来源、版本、目标环境与接口用途。
- 请求方法、路径、参数位置、必填条件与字段类型。
- 响应结构、成功条件、可空字段及业务状态。
- 登录与权限、凭证传递及敏感数据处理。
- 失败分类、错误提示、超时、取消和重试。
- 分页/排序/筛选规则。
- 写操作防重复、幂等责任及失败后的数据一致性。
- 需要转换的时间、单位、精度或枚举。
- 跨端、上传下载、缓存等专属约束。

已有请求封装和契约可直接引用，避免每次重抄全部字段。
仅在契约与页面模型存在实际转换、隔离或复用需求时增加适配层；字段可直接使用且符合项目规范时不强制建 adapter。
具体场景风险只在 frontend-risk-checks.md 维护：异步请求见 R1，缓存见 R2，金额日期见 R3，权限、写操作与敏感数据见 R4，生命周期与资源见 R6；只读相关章节，不把契约清单重复扩展为另一套风险表。

## Mock

只在用户授权的原型、演示或计划范围内使用 Mock，不为了绕开关键未知业务规则而编造行为。
数据覆盖当前任务所需状态，不建立多余模拟系统。展示数据不构成后端契约。
沿用项目环境机制，明确 Mock 的启用条件；开发环境可按项目默认启用，生产环境不得意外启用。
用户要求演示产物时可以保留已说明的 Mock；真实接口交付必须核对切换并清理本次废弃的临时逻辑。
报告明确哪些已接真实服务、哪些仍为模拟，以及未验证的交互。

## 契约冲突与执行中断

文档与响应不一致时记录来源、环境、脱敏差异及受影响任务；不能以时间较新或一次响应自动替代确认契约。
不私自写多套猜测兼容代码掩盖冲突。确认后按 change-control.md 判断是实现缺陷、契约澄清还是变更。
新依赖、工作区重叠、权限不足、关键输入缺失或需扩大范围时，记录具体解除条件，只暂停受影响任务及下游。
完整流程把阻塞写入 JSON 索引，不能只留一段“待确认”；常规流程写在当前任务记录。
可继续独立任务和解决阻塞本身，不反复请求已明确授予的权限。
