# UI 还原流程

页面需要按图片、截图或 Figma 设计还原，或需要还原明确动效时读取本文件。普通功能开发、已有样式内的小改动和纯逻辑任务不加载。
本文件定义 UI 来源、还原闭环和视觉证据；业务状态是否完整见 planning-and-ui.md，项目组件复用见 project-and-requirement-review.md，验证完成条件见 testing-and-delivery.md。

## 入口选择

- Figma 节点链接：优先使用 Figma MCP 入口。
- 本地图片、截图或切图目录：使用图片入口。
- Figma Prototype、动效标注、参考视频或明确动画要求：同时使用动效入口；静态来源未表达动效时不触发。
- 两类来源同时存在：分别记录用途和版本。Figma 通常提供结构、标注和变量，图片可补充批注、状态或目标效果；结论冲突时按已确认来源优先级处理，不能凭文件时间或工具输出自行取舍。
- 只有文字规格或项目既有页面：可作为 UI 依据，但不声称执行了图片或 Figma 还原。

开始前确认目标页面/组件、状态、运行端、目标视口、允许改动范围和来源。只缺某个状态或尺寸时，阻塞对应任务，不让整个需求停摆。
用户要求严格还原但没有可查看的来源、Figma 无访问权限或目标尺寸不明且会改变布局时，列出最少缺失输入；不凭经验补设计。

## Figma MCP 入口

本节工具名表示所需能力，以当前环境实际提供的工具和命名为准。名称或命名空间不一致时先查找明确等价的能力；无法确认等价能力时按本入口不可用处理。

1. 确认当前环境存在 Figma MCP，且用户提供的是带 node-id 的目标节点链接。文件级链接不能确定目标节点时，请用户提供具体节点，不猜 nodeId。
2. 调用 get_design_context 或等价设计上下文能力前，必须加载当前环境提供的 figma-design-to-code 或明确等价的前置 skill，并遵守其参数和错误恢复要求。前置 skill 缺失时不得调用该能力；已有可用的节点导出图、截图或资源时按实际资料转图片入口，否则说明缺失输入及受影响范围。
3. get_design_context 是结构、参考代码、截图和设计提示的主要来源。get_metadata 仅用于定位节点，get_screenshot 用于查看和验证，不能代替设计上下文。
4. 遵循当前 figma-design-to-code skill 的来源优先级理解设计；来源冲突时记录差异，不静默选择。
5. MCP 返回的参考代码不能直接当成目标项目代码。先匹配项目框架、组件、设计变量、响应式和状态组织，再实现缺失部分。
6. 图标和图片使用 Figma 导出的真实资源或项目中已确认相同的资源。临时资源地址不得作为长期业务依赖；资源落盘位置和命名遵循目标项目约定。
7. 一个节点过大或读取超时时，按页面区块或组件缩小节点范围后继续；保留各节点与目标区域的映射，不反复读取整份文件。

读取 Figma 不授权修改 Figma 文件。只有用户明确要求创建、修改或同步 Figma 设计时，才进入 Figma 写入流程并加载 figma-use 等对应规则。
当前环境没有 Figma MCP 或访问失败时，说明受影响范围；可请用户提供节点导出图和资源后转图片入口，不能假装读取过节点属性、变量或 Code Connect。

## Figma 来源变更检测

仅在任务跨会话恢复、等待外部回复后继续、执行时间较长，或交付前有合理可能发生设计变化时触发；一次会话内完成且来源稳定的小改动不重复读取。
首次读取时在当前任务记录或计划的 UI 依据中记录 fileKey、nodeId、带时区读取时间，以及工具实际提供的版本或来源标识；没有版本字段时不自行构造。恢复或交付前只重新读取本次使用的节点和状态，不扫描整份文件。
重新读取后核对相关结构、标注、变量、资源、截图和动效来源。没有变化时沿用已有计划、批准和证据；存在变化时记录具体差异，按 change-control.md 判断影响，只使受影响任务、批准和视觉或动效证据失效。
无法重新访问时记录未核对及影响范围。只有来源新鲜度属于验收条件时才阻止对应交付，不能在无证据时声称设计仍为最新版。

## 图片与截图入口

1. 使用可用的图片查看能力按原始清晰度读取相关图片，不只依据文件名或缩略图判断。
2. 记录文件名、尺寸、对应页面/组件、状态、目标端和已知基准视口；同一页面多张图按状态和尺寸映射，不按更新时间自动选择最终稿。
3. 提取与实现有关的布局层级、对齐、字体、颜色、间距、圆角、边框、阴影、图片裁切、滚动和响应式行为，并优先映射到项目已有组件及设计变量。
4. 核对正常、加载、空、失败、禁用、无权限和交互中状态中本次实际需要的部分。静态图未表达的跳转、动画、键盘和数据规则仍是未知信息，不能从像素推导业务行为。
5. 分析切图的格式、尺寸、透明区域、倍图及用途。资源缺失、重复或与截图冲突时记录具体位置；不自行绘制替代图标，也不把无关资源带入项目。
6. 图片无法证明字体文件、精确变量或隐藏结构时，结合项目实现判断；仍不能确定且影响验收时保留差异，不伪造精确值。

## 动效还原

仅还原来源明确表达且属于本次范围的动画、过渡和状态切换。Figma 包含 Prototype 或动效信息时，先加载当前环境对应的 Figma 动效实现 skill，再读取可用 motion context；参考视频按当前环境的视频动效还原能力读取。工具不可用时保留来源和人工核对步骤，不从静态帧补全未知时间线。
建立触发条件、起止状态、持续时间、延迟、缓动、方向、循环及中断行为的映射，只记录来源实际提供或项目已确认的值。动效实现匹配目标框架和项目模式，并核对目标平台性能及项目已有的减少动态效果规则。
动效验证使用实际交互或录屏与来源对照，覆盖本次要求的进入、退出、重复触发和中断状态。静态截图只能证明对应帧，不能单独证明动效通过；无法运行或录制时将动效验证记为未执行。

## 实现与视觉闭环

1. 建立来源映射：参考节点或图片、目标页面区域、状态和视口一一对应。
2. 检查项目现有页面、组件、Code Connect 和设计变量，确定直接复用、局部调整与必要新增；视觉相似不代表职责相同。
3. 先实现结构、内容流和主要状态，再处理视觉细节和响应式，避免在错误结构上反复微调。
4. 在用户和项目允许的环境中，以计划中的目标视口获取实现截图；不能运行页面时提供明确人工截图步骤并将结果记为未验证。
5. 将实现截图与对应来源并排、叠加或使用可用视觉比较能力核对，至少检查结构、位置、尺寸、文字换行、颜色、边框/阴影、资源裁切、溢出和状态。
6. 按影响修正差异并重新截图。只改造成差异的代码，不用全局样式覆盖局部问题，也不为单张截图破坏其他已确认尺寸。
7. 所有要求的页面、状态和目标尺寸完成核对后结束。项目或用户没有给误差标准时，以可观察差异逐项说明，不自创统一像素阈值或声称“像素级完全一致”。

## 视觉证据

每个视觉验证项记录：
- 来源类型、Figma 文件/节点标识或图片路径，以及来源版本或采集时间。
- 目标页面、状态、运行端、视口尺寸；设备像素比会影响结论时一并记录。
- 实现截图和比较方式；工具生成的数值差异只能作为证据，不能单独替代人工判断业务含义。
- 触发 Figma 变更检测时，记录重新读取时间、核对范围和结果。
- 涉及动效时，记录动效来源、实际交互或录屏、比较方式和未覆盖的时间线状态。
- 已核对范围、仍存在差异、差异原因、接受依据和未覆盖状态。
- 结果为通过、失败或未执行。无法访问 Figma、启动页面或取得目标端截图时不能标通过。

交付报告引用对应 V-* ID 和证据位置，不重复复制 Figma 节点数据或整份检查过程。截图含真实数据时先脱敏，Figma 和本地资源不得上传到未经授权的外部比较服务。
