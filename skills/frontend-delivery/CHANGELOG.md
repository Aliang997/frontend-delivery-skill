# Frontend Delivery 版本升级日志

当前版本以 SKILL.md 的 metadata.version 为准。本文件记录会影响使用方式、产物结构、状态兼容或维护职责的变化；普通措辞、排版和不改变行为的修正不单独记录。

版本号遵循语义化版本：不兼容的工作流或状态变化升级主版本，向后兼容的能力新增升级次版本，仅修正规则且不改变兼容性时升级修订版本。

## 2.2.0 - 2026-09-07

升级类型：向后兼容的 UI 与条件性风险能力补充。

- 新增按来源触发的动效还原，覆盖 Figma Prototype、动效上下文、参考视频、实现映射和实际交互或录屏证据。
- 新增 Figma 来源变更检测，仅在跨会话、外部等待、较长任务或交付前有变化可能时重新读取相关节点，并按影响局部失效任务、批准和证据。
- 新增国际化、主题、浏览器兼容、SSR/Hydration 和 SEO 五个独立触发维度；未命中的维度不加载、不验证。
- 为条件性风险增加按需项目事实采集入口，降低项目已经启用相关能力但 R8 未触发的风险。
- Figma 工具名按当前环境的等价能力识别；设计转代码前置 skill 缺失时不调用对应能力，已有导出资料可转图片入口。
- 保持网页 URL 还原不在本 skill 范围内；workflow-state.json 继续使用 schemaVersion 2，不增加状态字段。
- 流程图同步增加动效、Figma 来源变更检测和 R8 独立触发。

## 2.1.0 - 2026-09-07

升级类型：向后兼容的 UI 还原能力补充。

- 恢复图片、截图和切图还原入口，补齐来源映射、视觉分析、资源处理及多状态核对。
- 新增 Figma MCP 设计转代码入口，规定节点级读取、设计上下文、Code Connect、真实资源和目标项目适配边界。
- 新增实现截图与参考来源的对比、修正、复查和视觉证据闭环。
- Figma MCP 不可用时允许转为图片入口并明确能力限制；读取设计不授权修改 Figma 文件。
- 扩展 uiSourceType 以区分 figma 与 image，并兼容旧状态中的 local。
- 流程图在 2.0.0 主流程上补充图片与 Figma UI 还原闭环。

## 2.0.0 - 2026-09-07

升级类型：工作流与状态结构不兼容升级。

主要变化：
- 将统一五阶段流程改为小改动、常规需求和完整流程三级分流；执行终点继续由评审、计划和完整交付三种模式控制。
- 小改动默认直接处理；常规需求仅在跨会话、交接、多项待确认、等待外部回复或用户要求时创建 task.md；复杂或高风险任务才使用完整产物。
- 改为按任务 ID 和 taskVersion 管理批准及局部失效，未变化任务保留有效授权。
- 区分评审产出完成、需求确认、计划完成、实现完成、验证完成和发布就绪。
- 补充完整流程中断恢复、轻量文件指纹基准、流程升降级及旧状态迁移规则。
- 新增按场景读取的前端风险检查，覆盖异步请求、缓存、金额日期、权限与敏感数据、表单交互、性能多端及发布兼容。
- 衔接项目已有代码评审、CI 和发布要求，不自行创建平台，也不扩大执行权限。
- 统一本 skill 文本为 UTF-8 无 BOM、LF；读取兼容 LF 和 CRLF，业务文件遵循目标项目约定，并适配 Windows、macOS 和 Linux 路径。
- 流程图同步展示 2.0.0 的三级分流、执行终点、任务级批准、局部失效和产物职责。

状态兼容：
- workflow-state.json 使用 schemaVersion 2，并以 taskApprovals 替代旧版全局计划批准字段。
- 恢复旧状态时先保留和核对历史记录；只有能够证明批准范围、计划版本和当前任务一致时，才能映射为任务批准。
- 未知更高 schemaVersion 不做猜测性覆盖。

维护约定：
- 场景风险条目只在 references/frontend-risk-checks.md 维护。
- 状态字段和执行资格只在 references/state-machine.md 维护。
- 验证证据、工程门禁和交付条件只在 references/testing-and-delivery.md 维护。
- ui-restoration.md 引用的设计读取或写入、动效及视频还原属于条件性外部能力；其工具接口或前置 skill 调用约定变化时同步核对该文件，并按本日志的语义化版本规则升级。

## 1.0.0 - 2026-08-31

- 旧版未在 SKILL.md 声明正式版本号，本节按 2.0.0 前最后一份完整快照追认为 1.0.0。
